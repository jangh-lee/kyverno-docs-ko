이 가이드는 Policy-as-Code 솔루션을 평가하는 사용자를 돕기 위한 것입니다. Kyverno의 설계 원칙과 기능이 각 평가 기준을 어떻게 다루는지에 초점을 맞춥니다.

Kubernetes용 정책 엔진을 평가할 때는 조직에 중요한 핵심 기준을 이해해야 합니다. 이 가이드는 평가 기준을 하나씩 나누어 Kyverno가 각 요구 사항을 어떻게 충족하는지 설명합니다.

## 프로젝트 철학

Kyverno는 Kubernetes 관리자와 사용자가 정책을 쉽게 관리하도록 만들어졌습니다. 보안과 모범 사례를 위한 검증 검사가 주요 사용 사례이지만, Kyverno는 리소스 구성 수명 주기의 각 단계에 대응하는 정책 유형을 제공해 보안, 운영, 최적화 전반의 `정책 기반 자동화(Policy-Based Automation)`까지 다룬다는 점이 독특합니다. 플랫폼 엔지니어는 Kyverno로 보안뿐 아니라 수많은 자동화 사례를 쉽게 처리할 수 있습니다. 따라서 유지 관리, 보안 확보, 확장이 어려운 복잡한 커스텀 컨트롤러가 필요 없습니다.

## 정책 언어

**Kyverno의 접근 방식:** Kyverno는 정책 언어로 **YAML과 CEL(Common Expression Language)** 을 씁니다. Kyverno 정책은 YAML로 작성한 Kubernetes 리소스이며, 평가 로직은 CEL 표현식으로 넣습니다. CEL은 Kubernetes에서 널리 쓰이므로 모든 Kubernetes 사용자가 Kyverno를 바로 이용할 수 있습니다.

Kyverno는 Rego 같은 전문 정책 언어를 따로 배울 필요가 없으면서도, 더 쉽게 쓸 수 있는 강력한 기능을 제공합니다. 이 접근 방식의 특징은 다음과 같습니다.

- **학습 부담 최소화**: Kubernetes YAML에 이미 익숙한 팀이라면 새로 배울 것이 거의 없습니다.
- **Kubernetes 네이티브 구조**: 정책이 Kubernetes 리소스와 같은 모양입니다.
- **CEL 표현식**: 고급 검증 및 변환 로직에 씁니다.
- **타입 안전성**: Kubernetes OpenAPI 스키마와 CEL 컴파일로 확보합니다.
- **뛰어난 성능**: CEL 기반 정책은 성능이 훨씬 좋고 CPU와 메모리를 덜 씁니다.
- **높은 보안성**: CEL 표현식은 미리 컴파일되며 부작용 없이 샌드박스에서 실행됩니다. CEL은 튜링 완전하지 않아 무한 루프를 방지하고, 호스트 안전을 위해 리소스 한도를 둘 수 있습니다.

YAML 기반 접근 방식 덕분에 정책을 다른 Kubernetes 리소스와 같은 도구와 프로세스로 버전 관리하고 리뷰하고 관리할 수 있습니다.

## 도입 용이성

**Kyverno의 접근 방식:** Kyverno는 **직관적이며 Kubernetes 타입을 자연스럽게 확장하도록** 설계되었습니다.

Kyverno의 설계 철학은 Kubernetes 네이티브에 있습니다. 구체적으로는 다음과 같습니다.

- **익숙한 패턴**: 정책에 표준 Kubernetes 셀렉터(레이블, 네임스페이스, kind)를 씁니다.
- **추가 추상화 없음**: Kubernetes 리소스를 직접 다룹니다.
- **점진적 도입**: 단순한 검증 정책으로 시작해 차츰 복잡도를 높일 수 있습니다.
- **풍부한 문서**: 일반적인 사용 사례를 위한 종합 가이드와 예제가 있습니다.
- **정책 라이브러리**: 바로 쓸 수 있는 사전 제작 정책이 폭넓게 모여 있습니다.

개념이 이미 익숙한 Kubernetes 리소스 관리 패턴에 그대로 대응하므로, 팀은 최소한의 교육만으로 Kyverno를 쓰기 시작할 수 있습니다.

## K8s 리소스 검증

**Kyverno의 접근 방식:** Kyverno는 **포괄적인 Kubernetes 리소스 검증** 기능을 제공합니다.

Kyverno는 어드미션 제어 중 Kubernetes 리소스를 검증하는 데 뛰어납니다. 다음을 할 수 있습니다.

- 매치 규칙과 조건으로 **모든 Kubernetes 리소스를 검증**합니다.
- 복잡한 검증 로직에 **CEL 표현식을 사용**합니다.
- ConfigMap, 시크릿, 외부 API 호출 등 **외부 데이터를 참조**합니다.
- **리소스 간 관계와 의존성을 검증**합니다.
- **모범 사례와 보안 정책을 강제**합니다.

검증 정책은 리소스 스펙, 메타데이터, 리소스 간 관계를 검사할 수 있고 외부 데이터 소스를 기준으로 검증할 수도 있습니다. 그래서 Kyverno는 조직 정책, 보안 표준, 컴플라이언스 요구 사항을 강제하는 데 알맞습니다.

## K8s 리소스 변경

**Kyverno의 접근 방식:** Kyverno는 새 리소스와 기존 Kubernetes 리소스 모두에 **강력하고 유연한 변경(mutation) 기능**을 제공합니다.

변경은 Kyverno의 핵심 강점 가운데 하나입니다. 다음을 할 수 있습니다.

- 어드미션 중 리소스 필드를 **추가, 제거, 수정**합니다.
- **사이드카**와 init 컨테이너를 **주입**합니다.
- 누락된 필드에 **기본값을 설정**합니다.
- 패턴에 따라 **리소스 스펙을 변환**합니다.
- **레이블과 어노테이션을 자동으로 추가**합니다.
- **컨테이너 이미지와 리소스 requests를 수정**합니다.

Kyverno 변경은 선언적이고 멱등적이므로 여러 번 적용해도 문제가 없습니다. 따라서 여러 클러스터에서 리소스 구성을 표준화하고 일관성을 유지하는 데 이상적입니다.

## K8s 리소스 생성

**Kyverno의 접근 방식:** Kyverno는 리소스 생성이나 수정, 또는 기존 리소스에 대한 주기적 매칭 같은 유연한 트리거에 따라 **새 Kubernetes 리소스를 생성**할 수 있습니다.

리소스 생성은 Kyverno만의 기능으로, 다음과 같은 작업을 자동화합니다.

- 네임스페이스 레이블에 따라 **NetworkPolicy를 자동으로 생성**합니다.
- 템플릿으로 **ConfigMap과 시크릿을 생성**합니다.
- 디플로이먼트용 **PodDisruptionBudget을 생성**합니다.
- 수정을 거쳐 네임스페이스 간에 **리소스를 복제**합니다.

다른 리소스의 존재 여부나 구성에 따라 리소스를 자동으로 만들어야 하는 강력한 자동화 시나리오를 가능하게 하며, 수작업 운영 부담을 줄입니다.

## K8s 리소스 정리

**Kyverno의 접근 방식:** Kyverno는 리소스 수명 주기를 관리하는 **전용 정리 정책**을 제공합니다.

정리 정책으로 Kyverno는 다음을 할 수 있습니다.

- 스케줄이나 조건에 따라 **리소스를 자동으로 삭제**합니다.
- 부모 리소스가 삭제되면 **고아 리소스를 정리**합니다.
- 특정 기준을 더 이상 충족하지 않는 **리소스를 제거**합니다.
- 임시 리소스나 만료된 리소스를 **주기적으로 정리하도록 스케줄**합니다.

임시 테스트 리소스, 만료된 인증서, 정책을 위반하는 리소스처럼 더는 필요 없는 리소스를 자동으로 제거해 클러스터를 깔끔하게 유지할 수 있습니다.

## 이미지 검증

**Kyverno의 접근 방식:** Kyverno는 Sigstore Cosign과 Notary를 이용한 **네이티브 이미지 검증**을 제공합니다.

이미지 검증은 Kyverno에 내장되어 있으며 다음을 지원합니다.

- **Cosign v2 및 v3 형식**: Cosign으로 서명한 컨테이너 이미지를 검증합니다.
- **Notary v2**: Notary v2 서명을 지원합니다.
- **증명(attestation) 검증**: SLSA 프로비넌스와 그 밖의 증명을 검증합니다.
- **키리스 검증**: Sigstore의 키리스 서명을 지원합니다.
- **레지스트리 인증**: 프라이빗 레지스트리를 지원합니다.

Kyverno는 어드미션 제어 중 이미지를 검증해, 서명되고 검증된 이미지만 클러스터에 배포되게 합니다. 추가 도구나 복잡한 연동 없이도 강력한 공급망 보안을 확보할 수 있습니다.

## 런타임 제어

**Kyverno의 접근 방식:** Kyverno는 어드미션 제어를 넘어 **포괄적인 런타임 정책 강제**를 제공합니다.

많은 정책 엔진이 어드미션 시점의 검증에만 집중하지만, Kyverno는 다음을 제공합니다.

- **백그라운드 스캔**: 기존 리소스를 주기적으로 평가합니다.
- **정책 리포트**: 정책 준수 여부를 지속적으로 모니터링합니다.

따라서 정책은 생성 시점에만 강제되는 것이 아니라, 리소스를 지속적으로 모니터링하며 리소스 수명 주기 전체에 걸쳐 강제됩니다.

## 시프트 레프트, CI/CD 통합

**Kyverno의 접근 방식:** Kyverno는 Kyverno CLI로 **강력한 CI/CD 통합**을 제공합니다.

Kyverno CLI는 다음과 같이 시프트 레프트(shift-left) 방식을 가능하게 합니다.

- 클러스터에 배포하기 전에 **정책을 로컬에서 테스트**합니다.
- CI/CD 파이프라인에서 **Kubernetes 매니페스트를 검증**합니다.
- Terraform 플랜 같은 **IaC 매니페스트를 검증**합니다.

팀은 개발 초기에 정책 위반을 잡아 피드백 루프를 줄이고, 규정을 지키지 않는 리소스가 프로덕션 클러스터에 도달하는 것을 막을 수 있습니다.

## 모든 페이로드

**Kyverno의 접근 방식:** Kyverno는 Kubernetes 리소스뿐 아니라 **모든 JSON 페이로드**를 검증할 수 있습니다.

Kyverno JSON 정책과 ValidatingPolicy 리소스 유형으로 Kyverno는 다음을 할 수 있습니다.

- 같은 정책 언어로 **모든 JSON 구조를 검증**합니다.
- Kyverno JSON SDK로 **Kubernetes 밖에서 동작**합니다.
- **웹 서비스와 API와 통합**합니다.
- **설정 파일과 그 밖의 구조화된 데이터를 검증**합니다.

이런 유연성 덕분에 Kyverno는 Kubernetes 밖에서도 유용하며, 조직은 하나의 정책 엔진을 여러 사용 사례에 쓸 수 있습니다.

## 리포팅

**Kyverno의 접근 방식:** Kyverno는 [OpenReports](https://openreports.io)로 **포괄적인 리포팅**을 제공합니다.

Kyverno의 리포팅 기능은 다음과 같습니다.

- **PolicyReport**: 정책 결과를 담는 표준 Kubernetes 리소스입니다.
- **OpenReports API**: 새로운 OpenReports API 그룹을 지원합니다.
- **Reports Server**: 대규모 클러스터를 위한 확장 가능한 etcd 오프로드 솔루션입니다.
- **백그라운드 스캔 결과**: 주기적인 정책 평가의 리포트입니다.
- **리포팅 도구 연동**: 다양한 리포팅 UI와 호환됩니다.

리포팅 시스템은 클러스터 전반의 정책 준수 현황을 보여 주므로, 규정을 지키지 않는 리소스를 쉽게 찾고 정책의 효과를 시간에 따라 추적할 수 있습니다.

## 정책 예외

**Kyverno의 접근 방식:** Kyverno는 정책 면제를 관리하는 **전용 PolicyException 리소스**를 제공합니다.

정책 예외로 다음을 할 수 있습니다.

- 정책 강제에서 **특정 리소스를 면제**합니다.
- Kubernetes 리소스로 **예외를 선언적으로 정의**합니다.
- 네임스페이스, 리소스 이름, 레이블 또는 CEL 조건으로 **세밀하게 예외 범위를 지정**합니다.
- 정리 정책이나 TTL과 결합해 **예외에 기한을 설정**합니다.
- 표준 Kubernetes API로 **예외를 감사**합니다.

리소스가 표준 정책에서 벗어나야 하는 정당한 경우를 통제된 방식으로 처리하면서 가시성과 감사 가능성을 유지합니다.

## 테스트 도구

**Kyverno의 접근 방식:** Kyverno는 정책 개발을 위한 **포괄적인 테스트 도구**를 제공합니다.

Kyverno의 테스트 기능은 다음과 같습니다.

- **Kyverno CLI test 명령**: 샘플 리소스에 대해 정책을 테스트합니다.
- **Kyverno Chainsaw**: Kyverno 정책을 위한 고급 테스트 프레임워크입니다.

정책 작성자는 이 도구로 프로덕션에 배포하기 전에 정책을 개발하고 테스트하고 검증해, 정책이 기대한 대로 동작하고 기존 워크플로를 깨뜨리지 않는지 확인할 수 있습니다.

## 성능

Kyverno는 성능과 확장성에 맞게 최적화되어 있으며, 프로덕션 환경에서 의미 있는 결과가 입증되었습니다. 다른 이점과 더불어, OPA/Gatekeeper에서 Kyverno로 마이그레이션한 조직들은 성능이 크게 향상되었다고 보고했습니다(아래 참조).

새로운 CEL 기반 정책은 성능을 더 높여 줍니다. 자세한 리포트는 [스케일 테스트](/docs/installation/scaling/#scale-testing) 문서를 참고하세요.

### 커뮤니티 마이그레이션 사례

Kyverno 커뮤니티의 여러 조직이 OPA/Gatekeeper에서 Kyverno로 마이그레이션해 성능이 개선된 경험을 공유했습니다. 몇 가지를 소개합니다.

- [Adevinta](https://adevinta.com/techblog/why-did-we-transition-from-gatekeeper-to-kyverno-for-kubernetes-policy-management/)
- [Wayfair](https://nirmata.com/2023/11/29/why-how-wayfair-migrated-from-opa-to-kyverno/)
- [US DoD](https://docs-bigbang.dso.mil/latest/packages/kyverno/docs/gatekeeper/)
- [PwC](https://medium.com/@glen.yu/why-i-prefer-kyverno-over-gatekeeper-for-native-kubernetes-policy-management-35a05bb94964)

마이그레이션 계획을 세우는 데 필요한 더 자세한 정보는 [Gatekeeper 마이그레이션 가이드](/docs/guides/gatekeeper/)에서 볼 수 있습니다.

## 결론

정책 엔진을 평가할 때는 기능 목록만 보지 말고 다음도 고려하세요.

- 팀의 **도입 용이성**
- 사용 규모에서의 **성능 특성**
- 기존 도구와의 **통합**
- **커뮤니티 지원**과 문서
- **장기적인 유지 관리성**

Kyverno의 Kubernetes 네이티브 설계, 포괄적인 기능, 강력한 성능 특성은 Kubernetes 환경에 Policy-as-Code를 도입하려는 조직에 훌륭한 선택입니다.

특정 기능에 관한 자세한 내용은 [Kyverno 문서](/docs/)를 참고하거나, 바로 쓸 수 있는 정책이 모인 [정책 라이브러리](/policies/)를 둘러보세요.
