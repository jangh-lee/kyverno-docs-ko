Kyverno는 여러 기능을 별도의 컨트롤러로 분리해 두었고, 각 컨트롤러는 자체 디플로이먼트(Deployment)로 실행된다. 따라서 Kyverno를 고가용성으로 설치하려면 사용할 컨트롤러마다 레플리카를 추가해야 한다.

<a id="controllers-in-kyverno"></a>

## Kyverno의 컨트롤러

Kyverno는 네 개의 디플로이먼트로 구성되며, 각 디플로이먼트는 한 가지 유형의 컨트롤러를 실행한다. 컨트롤러는 Kyverno의 주요 기능 중 하나와 이를 지원하는 관련 컨트롤러를 맡는다.

### 어드미션 컨트롤러

- 검증 웹훅과 변경 웹훅으로 쿠버네티스 API 서버에서 AdmissionReview 요청을 받는다.
- 검증, 변경, 이미지 검증 규칙을 처리한다.
- 내장된 Cert Renewer로 웹훅에 쓰는 인증서를 시크릿(Secret)으로 관리하고 갱신한다.
- 내장된 Webhook Controller로 설치된 정책에 따라 웹훅 규칙을 동적으로 관리하고 구성한다.
- `ValidatingPolicy`, `ImageValidatingPolicy`, `MutatingPolicy`, `GeneratingPolicy`, `DeletingPolicy`, `PolicyException` 사용자 정의 리소스와 네임스페이스 범위 변형의 정책 검증을 수행한다.
- 정책 예외를 처리한다.
- 리포트 컨트롤러가 이어서 처리하도록 `EphemeralReport`와 `ClusterEphemeralReport` 중간 리소스를 생성한다.
- 백그라운드 컨트롤러가 이어서 처리하도록 `UpdateRequest` 중간 리소스를 생성한다.

### 리포트 컨트롤러

- 최종 `PolicyReport`와 `ClusterPolicyReport` 사용자 정의 리소스의 생성과 조정을 맡는다.
- 백그라운드 스캔을 수행하고, `EphemeralReport`와 `ClusterEphemeralReport` 중간 리소스를 생성·처리해 최종 정책 리포트 리소스로 변환한다.

### 백그라운드 컨트롤러

- `GeneratingPolicy`의 리소스 생성과 `MutatingPolicy`의 기존 리소스 변경을 처리한다.
- 정책 추가, 업데이트, 삭제 이벤트를 처리한다.
- 최종 리소스를 생성하거나 변경하기 위한 `UpdateRequest` 중간 리소스를 처리하고 생성한다.
- 리포트 컨트롤러가 이어서 처리하도록 `EphemeralReport`와 `ClusterEphemeralReport` 중간 리소스를 생성한다.
- 백그라운드 스캔에서는 리포트 컨트롤러와 관계가 없다.

### 정리 컨트롤러

- [DeletingPolicy](/docs/policy-types/deleting-policy)에 예약된 리소스 삭제를 처리한다.
- 레이블이 지정된 리소스의 [TTL 정리](/docs/guides/ttl-cleanup)를 처리한다.
- 컨트롤러 권한 범위에서 쿠버네티스 API로 일치하는 리소스를 삭제한다.

## Kyverno의 고가용성 동작 방식

이 절에서는 Kyverno가 고가용성 시나리오를 어떻게 처리하는지 설명한다.

### 어드미션 컨트롤러

어드미션 컨트롤러는 설치 유형이나 규모와 상관없이 모든 Kyverno 설치에 필요한 컴포넌트이다. 예를 들어 정책 리포트 기능만 필요하더라도 어드미션 컨트롤러는 설치해야 한다.

어드미션 컨트롤러는 들어오는 웹훅 요청에 리더 선출을 사용하지 않는다. 따라서 AdmissionReview 요청은 사용 가능한 모든 레플리카에 분산되어 처리된다. 고가용성 어드미션 컨트롤러 디플로이먼트를 지원하는 최소 레플리카 수는 3개이다. 인증서와 웹훅 관리 기능에는 리더 선출이 필요하므로, 이 작업은 한 번에 한 레플리카만 처리한다.

어드미션 컨트롤러에 레플리카를 여러 개 구성하면 가용성과 확장성을 모두 얻을 수 있다. 개별 레플리카의 리소스를 수직으로 늘려 전체 처리량을 높일 수도 있다.

### 리포트 컨트롤러

리포트 컨트롤러는 모든 리포트 처리 로직을 맡는다. 상태를 유지하는 서비스이므로 리포트 컨트롤러에는 리더 선출이 필요하다. 레플리카 수와 관계없이 리포트 처리는 한 번에 한 레플리카만 수행한다.

리포트 컨트롤러에 레플리카를 여러 개 구성하면 가용성만 높아진다. 개별 레플리카의 리소스를 수직으로 늘려 처리량을 높일 수도 있지만, 리더가 수행하는 처리에만 영향을 준다.

### 백그라운드 컨트롤러

백그라운드 컨트롤러는 생성 규칙과 기존 리소스 변경(mutate-existing) 규칙을 처리한다. 이 컨트롤러도 상태를 유지하는 서비스이므로 리더 선출이 필요하다. 어드미션 컨트롤러는 UpdateRequest를 여러 개 동시에 생성할 수 있지만, 레플리카 수와 관계없이 최종 리소스를 생성하거나 기존 리소스를 변경하는 일은 백그라운드 컨트롤러의 한 레플리카만 처리한다.

백그라운드 컨트롤러에 레플리카를 여러 개 구성하면 가용성만 높아진다. 레플리카의 리소스를 수직으로 늘리거나 이 프로세스가 사용하는 내부 워커 수(`--genWorkers`)를 늘릴 수 있다. 자세한 내용은 [컨테이너 플래그 절](/docs/installation/customization#container-flags)을 참고한다.

### 정리 컨트롤러

정리 컨트롤러는 쿠버네티스 API를 대상으로 예약된 삭제와 TTL 정리를 처리한다. 가용성을 위해 레플리카를 구성하고, 이 컴포넌트의 크기를 정할 때는 삭제 지연 시간과 컨트롤러의 리소스 사용량을 모니터링한다. 레플리카를 추가한다고 해서 같은 예약 삭제가 두 번 이상 실행되지는 않는다.

## 고가용성 모드로 Kyverno 설치

프로덕션 수준의 고가용성으로 Kyverno를 설치할 때는 Helm 차트를 권장한다. Helm 차트가 대부분의 프로덕션 요구를 충족하는 데 필요한 쿠버네티스 리소스와 구성 옵션을 모두 제공하기 때문이다. 고가용성 설치의 자세한 내용은 해당 [설치 절](/docs/installation/installation#고가용성-설치)을 참고한다.
